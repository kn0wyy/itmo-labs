# Что сделать и как защитить

## 1. Открыть новый проект
1. Останови старый Line Stats красным квадратом в основном окне VS Code. Старую папку удалять не требуется.
2. Распакуй enum-builder.zip. Перенеси enum-builder в Документы → ИСРПО.
3. File → Open Folder → enum-builder. Открывай папку с package.json непосредственно внутри.
4. Если появился Restricted Mode: Manage → Trust для этой проверенной папки.
5. Run → Start Debugging → Run Enum Builder. Отдельный Node.js устанавливать не нужно. Никаких npm install.
6. В новом окне Extension Development Host нажми кнопку Enum Builder внизу слева. Если её не видно: Cmd+Shift+P → Enum Builder: Открыть генератор.
7. Нажми «Сгенерировать». «Открыть C++ файл» покажет результат рядом. Сохранение — Cmd+S, например status.hpp. Для демонстрации сохранять необязательно.

Завтра повтори шаги 3, 5, 6. Не закрывай основное окно отладки во время показа. Если поменял код самого плагина, сохрани и перезапусти отладку.

## 2. Демонстрация за 3 минуты
В начале сдачи сообщи об использовании ИИ: это прямо требуется исходным заданием, даже если отдельного раздела в отчёте нет.

1. Введи `Status: New, Active=5, Done`. Сгенерируй. Покажи значения 0, 5, 6 и функцию toString. Объясни: «После заданной пятёрки следующее значение вычисляется как шесть».
2. Нажми «Открыть C++ файл»: код появится в соседнем редакторе. Покажи enum class и switch. Это готовый фрагмент C++11+, а сам плагин написан на JavaScript.
3. Вернись на вкладку Enum Builder. Введи `Status: New, New`. Покажи ошибку повторения имени.
4. Введи `Status: New=1, Active=1`. Покажи ошибку повторения числа. Объясни: одинаковые case в switch недопустимы.
5. Введи `Status: New=2147483647, Active`. Покажи обработку переполнения.
6. Введи `Status` без двоеточия. Покажи ошибку формата.
7. Верни правильный пример. Сгенерируй, нажми «Скопировать», создай Cmd+N и вставь Cmd+V.

Ожидаемые результаты выше — сценарий проверки. Сделай собственные скриншоты после запуска: форма с результатом, C++ файл рядом, ошибка дубля имени, ошибка переполнения. Скриншоты одногруппницы не являются доказательством работы нового плагина.

## 3. Что сказать про код
«В core.js я разделил разбор данных и генерацию от интерфейса. Вход разбивается на элементы, каждый проверяется. Массив items хранит имя и числовое значение; Set names и Set values выявляют дубли. next вычисляет следующее число. После проверки из массива строятся enum class и switch. Ошибки передаются в Webview и показываются в форме».

Не утверждай, что самостоятельно написал весь код, если это не так. Разбери эти функции перед сдачей.

Если спросят, почему не сниппет: «Есть разбор входа, вычисление значений, проверки, коллекции и генерация результата по данным пользователя».
Если спросят, зачем запрет повторов чисел: «Для однозначного toString и допустимого switch».
Если спросят, как UI общается с логикой: «Через сообщения postMessage».
Если спросят, зачем default: «Значение enum может быть получено приведением из неизвестного числа; тогда возвращается Unknown».

## 4. GitHub без множества отдельных репозиториев
Лучший вариант — один публичный учебный репозиторий `itmo-labs`, внутри папка `isrpo/lab03-enum-builder`. В дальнейшем остальные лабораторные складывай туда же. Репозиторий можно не закреплять в профиле. Пока сдаёшь, оставь доступ публичным: это требует условие. После завершения курса можно архивировать весь учебный репозиторий: он останется доступным, но станет только для чтения. Архивирование не скрывает его из профиля.

Простой путь через браузер:
1. GitHub → кнопка + → New repository. Имя itmo-labs, Public, Add README → Create repository.
2. На Mac создай папку itmo-labs, внутри isrpo, затем скопируй папку enum-builder туда и переименуй её lab03-enum-builder.
3. Открой её в Finder. Cmd+Shift+. показывает скрытые .vscode и .gitignore.
4. На странице репозитория Add file → Upload files. Перетащи папку isrpo. Не ZIP: преподавателю должны быть доступны обычные файлы.
5. Проверь, что среди загрузок есть .vscode/launch.json и .gitignore. Если скрытые файлы не загрузились, добавь их через Add file → Create new file с полными путями isrpo/lab03-enum-builder/.vscode/launch.json и isrpo/lab03-enum-builder/.gitignore; скопируй их содержимое из проекта.
6. Сообщение коммита: Add ISRPO lab 3. Нажми Commit changes.
7. Открой isrpo/lab03-enum-builder на GitHub. Скопируй URL этой папки в отчёт. Затем открой documentation.md и скопируй его адрес.
8. Проверь ссылку в приватном окне без авторизации. Код должен открываться.

Если itmo-labs уже существует, используй его — второй создавать не нужно. Не загружай .git, node_modules, весь каталог Документы, старый Line Stats или ZIP. Загружай только новый проект. Твои ФИО и группа в README станут публичными, как требует задание.

Инструкция GitHub: https://docs.github.com/en/repositories/working-with-files/managing-files-in-a-repository/adding-a-file-to-a-repository
Архивирование: https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories

## 5. Завершить отчёт
Вставь свои скриншоты вместо пометок и реальную GitHub-ссылку. Реализация описана в прошедшем времени; незаполненные результаты ручной демонстрации нельзя выдавать за уже выполненные. Проверь титульник и итоговые переносы страниц. Гарантировать решение преподавателя о зачёте невозможно: показывай расчёты и обработку ошибок, а не только внешний вид формы.
